# Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** schedularr running in the GXF cluster: GHCR image via CI semver releases, public Helm chart, ArgoCD Application, LAN HTTPRoute, sealed API-token secret, wiki/changelog aligned.

**Architecture:** Tasks 1–3 live in the schedularr repo (Dockerfile, Make targets, CI/release workflows, first tag). Tasks 4–6 follow the applicationset house workflow (chart in public helm-charts; Application + SealedSecret in applicationset; `helm-chart-validator` / `wiki-doc-synchronizer` / `change-tracker` agents run by the controller, not by implementer subagents). Task 7 is live verification.

**Tech Stack:** Docker multi-stage (node 22-alpine → hugomods/hugo or golang+hugo binary → golang:1.27 → distroless/static or alpine), GitHub Actions (bench-pattern plain docker), Helm, SealedSecrets, ArgoCD.

**Spec:** `docs/superpowers/specs/2026-08-29-deploy-design.md`

## Global Constraints

- schedularr repo: main-only, explicit-path commits, Conventional Commits, `make lint` stays exit-0, race suite green, feature-first, docs same commit, stop-slop prose.
- helm-charts repo is PUBLIC: infra-agnostic defaults ONLY (no geekxflood hostnames/storageclasses/node names). Real values live in the private Application.
- applicationset repo: wiki + CHANGELOG in the same commit set as manifests; `mkdocs build --strict` must pass; secrets never in git unencrypted (SealedSecret only); LAN-only HTTPRoute (public-exposure rule).
- Image: `ghcr.io/christopherime/schedularr`; cluster pins `vX.Y.Z`; linux/amd64.
- api/openapi.yaml and the Go/TS source are FROZEN for this plan except: Dockerfile, Makefile, .github/, web/public tracking, README/CLAUDE/AGENTS docs. Any app-code change needed is a finding to report, not to make.

**Files:**

**Interfaces:**

On `v*` tag — docker build with `VERSION=<tag>` and push `vX.Y.Z` + `latest` to GHCR (`permissions: contents: read, packages: write`; `docker login ghcr.io -u ${{ github.actor }} -p ${{ secrets.GITHUB_TOKEN }}` — bench pattern; GitHub-authored actions only: checkout, setup-go, setup-node).

- [ ] **Step 3:** Tag `v0.1.0`, push tag; verify release run green and the package exists (`gh api /user/packages/container/schedularr` or crane/docker manifest). Attempt ANONYMOUS pull check (`docker manifest inspect` unauthenticated or `crane manifest` without auth): if it fails because the package is private, STOP and report — the controller surfaces the one-click GitHub UI step (Package settings → Change visibility → Public) to the operator; do not attempt to change visibility with tokens.
