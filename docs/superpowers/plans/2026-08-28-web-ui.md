# Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hugo-built web UI (dashboard, blocks editor, schedule preview/apply, series-state panel) embedded in the schedularr binary and served at `/` by the existing router.

**Architecture:** `web/` Hugo site with Alpine.js and TypeScript modules bundled by Hugo's esbuild pipeline; TS types generated from `api/openapi.yaml`; a single typed fetch wrapper handles token auth and problem+json. `hugo` output (`web/public/`) is embedded via `go:embed` and mounted on the router's fallback path; `/api/v1` and system routes keep precedence.

**Tech Stack:** Hugo (brew, non-extended), Alpine.js (vendored single file), TypeScript + openapi-typescript (only node devDeps), Go 1.27, chi (existing).

**Spec:** `docs/superpowers/specs/2026-08-28-web-ui-design.md`

## Global Constraints

- Dev on `main` only; one task at a time; commit at task end with EXPLICIT `git add` paths (never `-A` — operator tooling drops stray files); push after every task. Conventional Commits.
- Feature-first: tests accompany, `make test` (race) green before commit; no TDD ceremony required.
- Docs updated in the SAME commit as the code they describe (README web section grows per task; CLAUDE.md/AGENTS.md trees in Task 1).
- Zero new golangci-lint issues (baseline 4 pre-existing). `tsc --noEmit` must pass from Task 3 onward (`make web-check`).
- **Every task that writes HTML/CSS/TS UI (Tasks 3–7) MUST invoke the `impeccable` skill (`Skill` tool, name `impeccable`) before writing UI code and follow it.** Prose (README etc.) follows stop-slop discipline: factual, no filler adjectives.
- Alpine.js is vendored (committed) at `web/assets/vendor/alpine.min.js` — no CDN, no npm runtime deps. Pin 3.x.
- The API contract is READ-ONLY for this plan: no edits to `api/openapi.yaml` (types are generated FROM it; if a UI need reveals a contract gap, report it — do not change the contract).
- All UI fetches go through `web/assets/ts/api.ts` — no bare `fetch()` in page modules.
- Token storage key: `schedularr_api_token` (localStorage). 401 → open the token panel.
