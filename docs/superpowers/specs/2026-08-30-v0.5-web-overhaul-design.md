# Schedularr v0.5.0 Web Overhaul — Design Specification

**Direction:** guide-first (adopted 2026-08-30)
**Status:** definitive. This document is the winning proposal strengthened with accepted grafts from the mission-control, flow-first, and craft-ceiling proposals. Accepted grafts are marked `(graft: <source>)` where they land; rejected grafts are recorded with reasons under Explicitly Out of Scope.
**Commit path:** `docs/superpowers/specs/2026-08-30-v0.5-web-overhaul-design.md`

---

## 1. Thesis

The guide IS the app. A TV scheduler has exactly one centerpiece object — the programme guide — and today Schedularr hides it behind a manual "Generate Preview" click that renders flat UUID-headed tables. v0.5.0 inverts the app around a full EPG grid as the home surface and the operator's primary mental model: channels are traces, time is the sweep axis, and the CRT graticule finally earns its "literal measurement grid" thesis by *becoming* the time ruler — one graticule division equals one 30-minute slot division.

Every other object hangs off the guide contextually. Click a slot to inspect its block and programs. See dropped occurrences as hatched "NO SIGNAL" ghosts exactly where they would have aired. Arm an apply as a diff overlay on the same grid. Watch the sweep-cursor now-line advance live over SSE. Blocks, Series, and a new Operations Log remain as bench pages, but they are workshops you visit *from* the guide — the guide answers "what airs, what didn't, and why" without leaving home.

Direct manipulation is deliberately bounded: slots derive from cron expressions, so dragging a slot would be a lie about the model. The guide is a precision readout you inspect and act from, never a canvas you smear. That restraint is itself the signal-bench identity.

Two graft-borne commitments deepen the instrument honesty:

- **The server owns time.** Cron evaluation stays in Europe/Zurich on the server; the client never parses a cron expression, and every next-occurrence readout is server-computed (graft: flow-first). The SSE heartbeat carries `server_time`, so the sweep cursor and every relative timestamp are drift-corrected instead of trusting the browser clock (graft: mission-control).
- **Success is printed, not toasted.** Every write confirms itself on an inline event tape — timestamped uppercase instrument-printout lines with at most one action (`UNDO`, `PREVIEW ON GUIDE`) — one idiom for the whole app, inside the no-toast rule (graft: craft-ceiling).

### Non-negotiables carried through every surface

- **Stack:** Hugo + Alpine.js, server-rendered nav with `aria-current`, no SPA framework, no client router, no new runtime dependencies. The EPG grid DOM is built in TypeScript from the typed response, with Alpine reserved for toolbar and inspector (graft: craft-ceiling — the concrete mitigation for grid performance).
- **CSP:** `style-src 'self'` — inline `style` attributes are silently dropped, so all dynamic slot geometry goes through CSSOM (`el.style.setProperty`, Alpine `:style` bindings). `connect-src 'self'`. This nuance is documented in DESIGN.md so a future contributor cannot "fix" it into broken inline attributes.
- **Auth:** bearer token in the `Authorization` header — which is why SSE uses a hand-rolled fetch-stream client, never `EventSource`, and never a token-in-query fallback.
- **Feedback:** no toasts, no spinners. Errors are inline `.problem` blocks (with a muted `REF <request_id>` line); successes are tape lines; busy states are `[aria-busy]` with a subdued sweep shimmer.
- **Coded legends (SC 1.4.1):** color never carries meaning alone — every status dot has adjacent text, every ghost slot has hatching *and* a label.
- **Motion:** 150–250ms, state-change-only, never on initial load, full `prefers-reduced-motion` parity (data still updates; transitions and trails are suppressed). `forced-colors` fallbacks for every box-shadow-borne state.
- **No-legacy-code policy:** superseded pages, bundles, and schema shapes are deleted outright in the same change — no deprecation aliases, no dual-shape transition periods, no redirect stubs. Contract breaks update the CLI and operator scripts in the same change.
- **Docs in the same change:** DESIGN.md, the wiki web-ui-guide, and screenshots are updated in every slice that changes what they describe.
- **Single operator:** no multi-tenant ceremony, no presence, no permissions UI.

### Roadmap headliners delivered

Auto-loading EPG guide as home · persisted apply runs + warnings ("why didn't X air last Tuesday" answerable in-app) · enriched history (titles, never UUIDs) · live updates over SSE with honest degradation · block duplicate and disable-until · series bulk operations and YAML import/export · typed schedule programs.

### Identity moves (the complete set)

1. **Sweep cursor** — the now-line as an oscilloscope sweep: accent vertical rule with a faint phosphor-persistence gradient trailing left, repositioned once per minute against server time. Pure function: it answers "what airs now."
2. **Graticule made load-bearing** — `--div` stops being decorative background and becomes the time division: one graticule square = 30 minutes of air time.
3. **No-signal ghost slots** — conflict-dropped occurrences render as hatched, scanline-textured ghosts at exactly the time they would have aired, labeled with the winning block.
4. **Trace draw-in** — live-changed slots and new log entries redraw with a single 200ms left-to-right opacity draw. Only on live change, never on load: motion exclusively means "the reading just updated."
5. **Bezel telemetry** — TUNARR / LINK / LAST APPLY as coded-legend dot+text readouts on every page, with one amber pulse on LINK LOST and one green pulse on reacquire.
6. **Channel legend plates** — `CH 04 · HORROR` machined-badge plates replace every UUID in the visible UI.
7. **The event tape** — timestamped uppercase printout lines as the system-wide success idiom (graft: craft-ceiling).

## 2. Information Architecture

Nav stays four items but changes meaning:

```text
GUIDE (/)  ·  BLOCKS (/blocks/)  ·  SERIES (/series/)  ·  LOG (/log/)
```

Two pages die under the no-legacy-code policy:

1. **Dashboard is retired.** Its status card (version, Tunarr signal, block count) generalizes into the persistent bezel telemetry strip visible on every page; its Recent History table merges into the Log. The route survives only until the Log exists (v0.5.3), then is deleted.
2. **The Schedule page is absorbed by the Guide.** Preview/apply becomes a draft *mode* of the guide itself — same grid, diff overlay, Apply in the guide's draft bar — not a separate destination. `schedule/list.html` and `schedule.ts` are deleted at v0.5.2.

The new **Log** (`/log/`) merges three currently scattered or missing records into one chronological operations feed: enriched airing history (titles, not UUIDs), apply runs (UI, CLI, and cron-loop applies alike), and persisted conflict warnings — making "why didn't X air last Tuesday" a filterable query instead of a dead end.

**Cross-page links become first-class.** Every block name anywhere links to its editor. Every channel renders as a legend plate (UUIDs survive only in DOM data attributes). Every guide slot's inspector links to the block editor and any involved series cursor. Every series row links to the guide at its next occurrence. Every log run links to the guide at that window; every warning links to both blocks involved. The 404 page is unchanged and carries the nav — deleted routes get no redirect stubs.

**Template infrastructure:** the copy-pasted skeleton/problem/empty-state/toggle/channel-picker/icon markup is extracted into Hugo partials; the four separate esbuild bundles collapse into one shared runtime module plus thin per-page entries (killing the `window.schedularr` cross-bundle `ApiError` identity hack and the 4x-duplicated helpers); the `page_js` boilerplate becomes one bundling partial carrying the cronstrue-before-page ordering constraint.

### First-run path (named acceptance flow) *(graft: flow-first)*

Every release must keep this chain unbroken, with each step's next action on screen:

1. Token panel → Save probes `GET /status` → dot flips ARMED only on success → every 401'd section re-fires automatically.
2. Guide teaching empty state → points at Blocks.
3. Blocks teaching empty state → NEW BLOCK.
4. Save → tape prints `BLOCK SAVED — PREVIEW ON GUIDE` with `reaches Tunarr at <next_cron_tick>`.
5. Guide opens in draft mode showing the diff → APPLY (confirm with real counts).
6. Committed grid redraws; tape prints the applied line linking to the Log run.

Zero dead ends: this is an acceptance test, not aspiration.

## 3. Surfaces

### 3.1 The Guide (home, `/`)

**Layout.** Full-bleed horizontal EPG escaping the content max-width: sticky left rail of channel legend plates (`CH` number + name + per-channel status dot), sticky top time ruler, channel rows as horizontal tracks scrolling on their own x-axis inside the content region — the page body never scrolls sideways. One day-window renders at a time (default: today). Navigation is **week-paged** (operator directive 2026-08-30, replacing the original flat tab strip): a `‹` / `›` week pager flanks seven day tabs — page N shows days N*7..N*7+6 of the loaded window, chevrons disable at the window's edges, and every tab always carries its weekday + date label. Slot faces show their content: series blocks list their programs (`SHOW · SxxEyy`, one per line as height allows, `+N more` overflow), filter blocks keep block name + program count; narrow slots degrade to name + count. A compact guide toolbar carries the plan controls: DAYS (1–30, clamped; default 7) and SCOPE (channel picker / ALL). Day tabs are navigation only and never arm a draft; changing DAYS or SCOPE flips into draft mode (3.3). Slots are bordered blocks positioned on a 5-minute quantum via CSS grid line numbers set through CSSOM, sized by real program durations from the typed schedule payload. The grid DOM is built in TS from the response; Alpine drives only toolbar and inspector. The 30-minute column width IS `--div` — graticule background lines and slot boundaries coincide exactly, and the ruler doubles as the measurement grid.

**Hierarchy.** Slots are primary: block name, time range, program count on the face, type-badge tint as a secondary scan aid (type is also in text). Past slots dim slightly behind the sweep. Ghost slots read amber-hatched with a text label. Ruler, plates, and graticule stay quiet chrome.

**Focal moment.** The sweep cursor — a thin accent now-line with a faint phosphor-persistence gradient trailing left, advancing once per minute against heartbeat-corrected server time; the auto-scroll target when the page opens. Under reduced motion it is a static repositioned rule with no trail.

**Interactions.** Auto-loads `GET /schedule` on open — the manual Generate click is dead. Click or Enter on a slot (or ghost) opens the inspector. Keyboard: slots participate in a roving tabindex; Left/Right move along a track, Up/Down move across channels, Enter opens, Esc closes with focus return. Ghost slots carry the conflict verdict into the inspector. When a live invalidation lands while the operator is inspecting or drafting, the grid never redraws under them — a pinned `LINEUP CHANGED — REFRESH` line appears instead (graft: mission-control); when the guide is idle in committed mode and the tab is visible, it refreshes itself with the trace draw-in, because a live instrument updates its trace.

**States.** Loading: a grid-shaped skeleton of pulsing track bars aligned to divisions. Tunarr down: the 404 page's scanline `NO SIGNAL` treatment across the grid area with RETRY and a teaching line linking to the Log for the last committed lineup — an honest instrument reading. Empty (no blocks): teaching state pointing at Blocks. Warnings from the current plan render as ghost slots in place (`NO SIGNAL — lost to Spooky Saturday Night`).

### 3.2 Slot inspector

**Layout.** A right-side rail panel on desktop — the grid compresses, never overlays, so the guide stays visible while inspecting; a bottom sheet on mobile. Opened from any slot or ghost; closed by Esc/X with focus returned to the slot.

**Hierarchy.** Header first: block name (linking to its editor), channel plate, time range with duration readout. Then the full program rundown with per-program start times and SxxEyy markers (typed program shape). Then the block's cron + cronstrue readback, priority with rank context (`50 · 2nd of 5` among same-channel blocks — graft: flow-first), and enabled state. For ghost slots: the conflict verdict naming the winning block, linked.

**Focal moment.** The rundown itself — the one place a slot's exact contents are legible without leaving the guide.

**Interactions.** `EDIT BLOCK` deep-links to `/blocks/` with the editor open on that block. `JUMP SERIES CURSOR` links to the `/series/` row for series blocks. `DISABLE BLOCK` is an inline toggle (PATCH-backed) with confirm; the tape prints the result with `UNDO`.

**States.** Every action button carries a loading state; errors render as inline `.problem` within the panel.

### 3.3 Draft & apply mode (guide overlay)

**Layout.** The same grid, second layer. Entry: changing DAYS/SCOPE in the toolbar, or arriving from a block save via `PREVIEW ON GUIDE`. A `POST /generate` preview renders as a diff overlay: new/changed slots draw in with an accent left edge, removed slots ghost out with strikethrough hatching, unchanged slots dim to background. A sticky draft bar sits above the grid: `DRAFT — 14 SLOTS ACROSS 3 CHANNELS, 1 DROPPED` with APPLY / DISCARD.

**Hierarchy.** The diff is the content; the draft bar is the armed control; everything else recedes.

**Focal moment.** The diff overlay itself — the operator sees the plan change *on* the guide, not in a separate table.

**Interactions.** The armed-signature discipline is preserved: Apply sends exactly the previewed request; any control change disarms and requires re-preview. Live data deepens it: a `plan.invalidated` event during a draft disarms Apply and flips the draft bar to an amber `SOURCE CHANGED — RE-PREVIEW` legend — the instrument never applies a reading it knows is stale. Apply uses the shared confirm dialog naming scope and real counts, then `[aria-busy]` with the legend `APPLYING…`. On success the overlay collapses with a 200ms settle, the committed grid redraws, warnings from the run pin as ghost slots immediately, and the tape prints `21:14:02 APPLIED — 14 SLOTS / 3 CHANNELS — VIEW RUN` linking to the Log entry.

**States.** Preview loading (busy Generate), armed, disarmed-stale (amber), applying, applied (tape line), apply error (inline `.problem` with `REF`). This surface deletes `schedule/list.html` and `schedule.ts` entirely.

### 3.4 Bezel telemetry strip (shell)

**Layout.** The existing sticky header bezel gains a compact instrument cluster on the right, next to the token trigger: `TUNARR` (signal dot + label), `LINK` (`LIVE` / `POLL` / `LINK LOST` — the SSE legend), and `LAST APPLY` (relative time from `Status.last_applied_at`, skew-corrected). Present on every page — the dashboard's status card generalized into persistent chrome.

**Hierarchy.** Three coded-legend dot+text pairs, equal weight; the token trigger keeps its place.

**Focal moment.** A LINK state change: one 200ms amber pulse on LINK LOST, one green pulse on reacquire — the arming-dot glow vocabulary extended to the app's live connection.

**Interactions.** Clicking TUNARR or LINK opens a small positioned popover (not a dialog) with detail: `tunarr_error` text, reconnect countdown, `next_cron_tick` readout, and a manual RETRY/RECONNECT action. The token dot finally means something: Save probes `GET /status` and flips ARMED only on success, and arming broadcasts a re-auth event that re-fires the current page's failed loads — the per-section-Retry-after-401 grind dies.

**States.** Narrow viewports collapse the cluster to dots-only with an expandable sheet; the nav gets its compact scrollable tab row.

### 3.5 Blocks bench

**Layout.** The two-zone page stands (toolbar + list, inline editor panel above the list — a multi-minute task stays inline, never modal), but both zones are rebuilt on the kit.

**List.** Columns: Name · Type badge · Schedule (cron + readback) · NEXT (server-computed `next_occurrence`, rendered `THU 21:00`; a `DARK UNTIL 12 SEP` countdown chip when `disabled_until` is set) · Duration · PRI with rank context (`50 · 2nd of 5`) · Channel plate · Enabled toggle (PATCH-backed) · row actions Edit / Duplicate / Disable-until / Delete, all sharing the one confirm idiom. Duplicate calls the new endpoint and opens the editor on the copy with the name (`Copy of …`) focused for rename. Disable-until is a small popover with presets — 1 day / 1 week / until date — writing `disabled_until` via PATCH. The two competing error surfaces (`listError`/`blocksError`) collapse into one `.problem`.

**Editor.** Form left, **consequence rail** right (graft: flow-first — richer than an inline readback, and it retires the save-then-preview round-trip): the next 3 occurrences with computed end times (start + duration) from `BlockRecord.next_occurrences`; while the cron field is dirty, a debounced `GET /cron/next` re-reads the draft expression server-side and the rail labels itself `DRAFT`; priority position among channel siblings, listed; and for series blocks the projected episode lineup, client-projected deterministically from cursor + order + eps/block, updating live on reorder. Series rows compress to summary lines (`2 · SUPERNATURAL · 1 EP/BLOCK · FROM S1E1`) expanding one at a time, halving the current half-viewport-per-row height. Editing cron on a committed series block raises an explicit confirm explaining the occurrence-skip footgun with the one-click compensating rewind offer. Save is a `PUT` with `If-Match: <updated_at>`; a 412 renders "reload and re-apply your edit."

**Focal moment.** Save: the editor closes with a 200ms settle and the tape prints `BLOCK SAVED — PREVIEW ON GUIDE`, with `reaches Tunarr at <next_cron_tick>` — the create→apply bridge.

**Interactions.** Dirty-editor guard (graft: mission-control): `plan.invalidated`/blocks changes arriving while the editor is open never refetch the list under it; a change to the *open* block raises an inline amber `THIS BLOCK CHANGED ELSEWHERE — RELOAD` note. Queued refetches run when the editor closes.

**States.** Table-row skeletons; teaching empty state; 409 renders under the name field; every input carries focus/invalid treatment; the save button carries `[aria-busy]`.

### 3.6 Series desk

**Layout.** The single-table page upgraded to a selection-capable desk: a leading checkbox column plus header select-all arms a sticky bulk action bar above the table when ≥1 selected — RESET CURSOR, ADVANCE SEASON, MARK COMPLETED, DISABLE / ENABLE — each confirming with the count, executed via the bulk PATCH with per-title outcomes (partial failures render inline per row).

**Hierarchy.** Cursor context first: `S1E2 of S5 · 112 eps` (from `MediaShow.seasons`) next to the cursor inputs, with client-side bounds validation flagging out-of-range before save. A next-occurrence link jumps to the guide slot where the show airs next.

**Focal moment.** A bulk operation completing — affected rows take the trace draw-in as their new values land, and the tape prints `5 CURSORS RESET`.

**Interactions.** The convention is named: settings snap, data arms. Completed/Disabled toggles stay instant but print an undoable tape line (`SUPERNATURAL DISABLED — UNDO`, live for 10 seconds, reverting via the same PATCH); cursor S/E edits stay dirty-armed behind Save. Toolbar IMPORT/EXPORT: export downloads the YAML; import is a file picker → dry-run preview table (names, changes) → commit — the blocks YAML round-trip pattern applied to series state.

**States.** Row skeletons; per-row errors with the existing refresh recovery; teaching empty state: "Rows appear after a series block first airs — create one on Blocks."

### 3.7 Operations log (`/log/`)

**Layout.** A single-column chronological feed with a filter toolbar: window 1–90 days, channel, block, event type (applies / warnings / aired). Two record kinds, visually distinct: **APPLY RUN** entries as bordered instrument cards — timestamp, source badge `UI`/`CRON`/`CLI`, scope, slot × channel counts, persisted warnings expandable inline, each naming loser, winner, and would-have-aired time with both blocks linked; and **AIRED** entries as compact rows grouped by day — local time, channel plate, block link, program title + SxxEyy. Failed runs carry the error detail and `REF` line.

**Hierarchy.** Runs are cards, airings are rows; amber warning chips make trouble scannable.

**Focal moment.** Expanding a run — a 200ms disclosure revealing its warnings and per-channel summary. This page closes journey 4: "why didn't X air last Tuesday" = filter to the block + that week, read the persisted warning.

**Interactions.** A run links to the guide at that window; a warning links to both blocks. New SSE-driven entries prepend with the trace draw-in.

**States.** Feed-shaped skeleton; teaching empty state that explains the cron loop writes here too, and that runs cannot be backfilled from before the migration. Server retention: 90 days, pruned in the same migration that creates the tables (graft: craft-ceiling).

## 4. Component System & Tokens (deltas to `web/DESIGN.md`)

### Partials (`web/layouts/partials/ui/`)

- `skeleton` — bar/stack/row + new **table-row** and **grid-track** variants; widths via modifier classes (CSP rule).
- `problem` — the single error idiom (title/detail/retry slot + muted `REF <request_id>` line for log correlation); the blocks page's competing error surfaces collapse into it.
- `empty` — teaching empty state: legend line, one sentence, one action.
- `toggle` — the one already-state-complete control, shared instead of pasted.
- `channel-select` — with an explicit channels-loading state, ending the raw-text-input ambiguity; resolves names via the runtime's `/channels` cache.
- `plate` — the channel legend plate (`CH 04 · HORROR`); the UUID-replacement idiom everywhere.
- `icon` — one inline SVG sprite, ending path duplication.
- `confirm` — one native `<dialog>` idiom for apply/delete/bulk, with max-height/overflow for small viewports; ends the three-pattern drift.
- `tape` — the event tape region: timestamped uppercase lines, newest first, max 3 retained, at most one action per line; no auto-dismiss, no stacking, reduced-motion prints without animation (graft: craft-ceiling).
- `page-js` — bundling boilerplate + the cronstrue-before-page ordering constraint, centralized.

### Runtime (TS)

One shared bundle imported by thin page entries: typed API client with `AbortController` timeouts and a paths-bound surface (a typo'd path no longer compiles), single `ApiError` identity (the `window.schedularr` hack dies), formatting, error-describing, channel labeling, the event bus + SSE client, the tape controller, entry guards on every mutating call, and the grid renderer module (TS-built DOM; Alpine only for toolbar/inspector). The module-level one-shot `started` init guards are retired for a subscribe-on-init lifecycle.

### Token deltas

- z-scale: `--z-bezel` / `--z-sticky` / `--z-popover` / `--z-dialog`.
- `--glow-accent` (names the armed-dot ring), `--shadow-dialog`.
- One icon-size token collapsing today's three drifting values; measure tokens (`--measure`, `--content-max`) with the guide's full-bleed exception named.
- Warn/danger tinted surfaces via `color-mix` — ghost slots, draft-stale legend, warning chips stop sitting on plain `bg-inset`.
- `--duration-slow: 250ms`.
- `--div` rewired as load-bearing: it governs the guide's 30-minute column. The CSSOM rule (inline `style` attributes silently dropped under `style-src 'self'`; geometry via `setProperty`) is documented beside it.

### Component-state floor

Inputs gain focus and invalid treatment (`[aria-invalid]` danger border + focus-within); buttons gain a loading state (`[aria-busy]` with a subdued sweep shimmer); hover rules gain `:not(:disabled)` guards; `forced-colors` fallbacks cover every box-shadow-borne state; the two form-field vocabularies unify into one field system. Every new color pairing (warn tint, ghost hatch, draft dashed edge) gets a computed WCAG check in both palettes per the DESIGN.md evidence discipline.

### The `/kit/` page (dev-only) *(graft: craft-ceiling)*

A Hugo dev-environment-only page — excluded from production builds — rendering every partial in every state. It is the review gate: a slice is not done until its new states appear on `/kit/`. This is what keeps the floor from eroding across eight slices.

### DESIGN.md itself

Rewritten in the polish slice from retrospective document to current contract: dark front-matter values, the CSP/CSSOM nuance, the tape/plate/ghost idioms, the graticule coupling, and recaptured screenshots.

## 5. Motion

Budget: 150–250ms, state-change-only, never on initial load, reduced-motion parity always (data updates; transitions, trails, and pulses are suppressed; the sweep becomes a static repositioned rule). The complete inventory — nothing else moves:

1. **Sweep cursor** — per-minute reposition with phosphor-persistence trail (Guide).
2. **Trace draw-in** — 200ms left-to-right opacity on live-changed slots and prepended log entries; only on live change.
3. **Draft overlay** — accent-edge draw-in for added slots, ghost-out for removed; 200ms settle collapse on apply success.
4. **Bezel pulses** — one amber pulse on LINK LOST, one green on reacquire; the existing token armed glow.
5. **Tape print** — newest line, 150ms.
6. **Disclosures** — log run expand, series-row expand, 200ms.
7. **Busy shimmer** — `[aria-busy]` subdued sweep inside buttons.
8. **Bulk bar** — 150ms slide-in on first selection.

The scanline flicker remains reserved for signal loss: the 404 page and the guide's Tunarr-down state, nowhere else. Nothing loops; the sweep's minute advance is a discrete step, not an animation loop.

## 6. Live Data (SSE)

**Transport.** `GET /api/v1/events`, `text/event-stream`, consumed by a hand-rolled `fetch()` + `ReadableStream` client (~60 lines in the shared runtime) — `EventSource` cannot send the `Authorization` bearer header, and a token-in-query alternative would leak the token into logs. Same-origin, `connect-src 'self'`, no new dependency, no infra.

**Server.** A goroutine-per-subscriber broadcast hub. Heartbeat every 15s as a real event carrying `{server_time}` — it defeats proxy buffering *and* gives the client a drift-corrected clock (graft: mission-control; this fixes the class of bug behind the `schedule.ts:332` appliedSummary skew for good). Monotonic event ids; `Last-Event-ID` resume from a small ring buffer.

**Events.**

```text
heartbeat        {server_time}
apply.completed  {run_id, source, channel_ids[], slot_count, warning_count, applied_at}
plan.invalidated {reason: block|series, id}
status.changed   {tunarr_reachable}
history.appended {run_id}
series.changed   {show_title}
```

**Routing.**

- Bezel ← `status.changed` directly; `heartbeat` updates the skew offset (smoothed `server_time − Date.now()`) applied to the sweep cursor, LAST APPLY, and every relative timestamp.
- Guide ← `apply.completed` / `plan.invalidated` → refetch `GET /schedule` (debounced 2s) with trace draw-in — but only when idle in committed mode with the tab visible. While the inspector is open or a draft is active: pinned `LINEUP CHANGED — REFRESH` line, and a draft additionally disarms with `SOURCE CHANGED — RE-PREVIEW` (graft: mission-control).
- Log ← `apply.completed` / `history.appended` → prepend.
- Blocks / Series ← their change events → refetch, unless an editor is dirty (queued until close; an external change to the open block raises the inline reload note, never a clobber).
- The sweep advances on a local 60s timer corrected by the heartbeat offset — not on the stream.

**Lifecycle.** Subscribe-on-init replaces the one-shot guards: init = fetch once + subscribe. `visibilitychange` pauses the stream when the tab is hidden and, on visible, reconnects and refetches the current page's primary GET (graft: flow-first).

**Degradation ladder.** Stream error → exponential backoff 1s→30s resuming from `Last-Event-ID`, LINK reads `LIVE` still attempting; after 3 consecutive failures → 60s polling of `/status` + the page's primary GET, LINK flips to `POLL`; dead network → `LINK LOST` with a manual reconnect action. Nothing functional requires the stream — every page remains fully operable with manual refresh, and reduced-motion suppresses the draw-in while data still lands. The SSE endpoint sets no-buffering headers; the future oauth2-proxy fronting (v0.9) must pass streams through — recorded as a standing integration requirement.

**Concurrency hardening (mandatory once multi-writer visibility exists).**

- `PUT /blocks/{id}` requires `If-Match: <updated_at>`; mismatch → 412 with a "reload and re-apply your edit" problem.
- Toggles and pause-until use `PATCH /blocks/{id}` — field-scoped writes that cannot lose unrelated edits (graft: craft-ceiling; complements If-Match rather than replacing it).
- The dirty-editor and dirty-draft guards above complete the story for v0.5.x.

## 7. Mobile Strategy

Principle: **structural reflow, never shrink**. Instrument panels do not hide their controls behind a hamburger.

- **Guide** collapses to a vertical day-grouped rundown: `TONIGHT` / `TOMORROW` headers, one chronological slot list per channel behind a channel picker, the now-line as a horizontal rule. Draft mode works identically on the rundown — added/removed markers per row, same sticky draft bar.
- **Inspector** becomes a bottom sheet with an explicit close affordance and focus return.
- **Bezel** collapses to dots-only with an expandable detail sheet; the nav becomes a scrollable tab row with scroll-edge fades.
- **Dialogs** get max-height and internal overflow for small viewports.
- **Tables** (Blocks, Series, Log aired rows) live inside their own `overflow-x` containers with sticky headers and scroll-edge fades — the page body never scrolls horizontally. Full card recomposition for Blocks/Series is deliberately deferred (see Out of Scope): v0.5.x mobile investment concentrates on the Guide, the daily-use surface.
- Touch targets meet the floor everywhere; the v0.5.7 polish slice runs the full audit.

## 8. OpenAPI Contract Additions

### New endpoints

#### `GET /api/v1/events`

SSE live-update stream. `Accept: text/event-stream`; bearer auth via `Authorization` header; supports `Last-Event-ID` resume. Emits the event catalog in §6, including `heartbeat {server_time}` every 15s. No-buffering headers set server-side.

#### `GET /api/v1/applies`

Persisted apply-run history. Query: `days` (1–90, default 7), `channel_id?`, `limit?`.

```text
200 → ApplyRun[]
ApplyRun {id, applied_at, source: ui|cron|cli, days, channel_id?,
          slot_count, channel_count, warnings: Warning[]}
```

Backed by a new migration (runs table + per-run persisted warnings); **all** apply paths write — UI, CLI, and the cron loop. Retention: rows older than 90 days pruned server-side, policy shipped in the same migration (graft: craft-ceiling).

#### `POST /api/v1/blocks/{id}/duplicate`

Body `{name}` → `201 BlockRecord` (atomic copy, series seeds/config intact); `409 Problem` on name collision (UI pre-fills `Copy of …`).

#### `PATCH /api/v1/blocks/{id}`

Field-scoped write for toggles: body `{enabled?, disabled_until?}` → `200 BlockRecord`. No If-Match required. (graft: craft-ceiling)

#### `GET /api/v1/cron/next`

Query: `expr` (cron), `count` (1–10, default 3), `from?` (RFC3339, default now).

```text
200 → {occurrences: RFC3339[]}   400 Problem on invalid expr
```

Server-evaluated in Europe/Zurich. Powers the consequence rail's draft readout and schedule-picker validation; exists so the client never parses cron (completes the flow-first graft without a JS cron dependency).

#### `PATCH /api/v1/state/series`

Bulk series operation: body `{show_titles: string[], patch: SeriesStatePatch}`.

```text
200 → {results: [{show_title, ok, state?, problem?}]}   (partial success allowed)
```

#### `GET /api/v1/state/series/export` · `POST /api/v1/state/series/import`

Export: `200 application/yaml` series-state dump. Import: `application/yaml` body, `?dry_run=bool` → `200 {imported, dry_run, names[]}`; `400/409 Problem`. Mirrors the blocks YAML round-trip.

### Extended endpoints & schemas

#### `GET /api/v1/schedule` — extend

Add `channel_id` query param (parity with `GenerateRequest`). Replace `ScheduledSlot.programs` `additionalProperties: true` with:

```text
ScheduledProgram {title, type?, season?, episode?, duration_ms, start_time}
```

The same typed shape flows into `PlanResult` for `/generate` and `/apply`. This is a hard swap, pre-v1.0: the CLI and any operator scripts are updated in the same change; no dual-shape transition (per no-legacy-code policy).

#### `GET /api/v1/history` — extend

`HistoryEntry` gains `title, type, duration_ms, occurrence_start, sequence, run_id` (columns present since migration 000003, today stripped at the wire; `run_id` joins airings to their `ApplyRun`). Add query params `channel_id?`, `block_name?` alongside `days`. The program-UUID column dies.

#### `Warning` — extend

Add `channel_id` and `duration_minutes` to `{block_name, blocking_block_name, occurrence_start}` — required to place ghost slots on the grid, live and historical.

#### `GET /api/v1/status` — extend

Add `last_applied_at` (nullable RFC3339, from `applied_channels`) and `next_cron_tick` (nullable RFC3339) (graft: flow-first) — feeds the bezel LAST APPLY readout and the create→apply bridge line without extra requests.

#### `BlockSpec` — extend

Add `disabled_until` (nullable RFC3339): the planner skips the block until that instant, then it is automatically live again. Surfaces as the Disable-until popover and the `DARK UNTIL` chip.

#### `BlockRecord` — extend

Add `next_occurrence` (nullable RFC3339) and `next_occurrences` (RFC3339[], 3) — server-computed in Europe/Zurich (graft: flow-first; replaces the client-side cron evaluation the winning proposal originally specified, which was a timezone footgun).

#### `PUT /api/v1/blocks/{id}` — extend

Require `If-Match: <updated_at>` → `412 Problem` on mismatch ("reload and re-apply your edit"). Lost-update protection for full-spec edits.

#### `GET /api/v1/media/shows` — extend

`MediaShow` gains `seasons: [{season, episode_count}]` — enables cursor bounds validation and the `S1E2 of S5 · 112 eps` context.

## 10. Explicitly Out of Scope

**Rejected grafts and runner-up ideas (with reasons):**

- **ON AIR now/next board and `GET /onair`** (mission-control) — planned-not-measured: Schedularr knows the applied lineup, not what Tunarr is actually emitting; an instrument that renders a reading it cannot measure lies. Proxying Tunarr playback state is out for all of v0.5.x.
- **Station clock in the bezel** (mission-control) — chrome without a question it answers; `server_time` drives the readouts silently instead.
- **Console page / fifth nav item** (mission-control) — the bezel strip and the Log absorb every console function; the guide-first thesis keeps home for the guide.
- **Two-phase apply events (`started`/`completed`)** (mission-control) — single-operator ceremony; `apply.completed` suffices.
- **PRI lane-bar visualization** (flow-first) — the textual rank (`50 · 2nd of 5`) carries the information; the bar is decoration.
- **Client-side cron evaluation** (originally in the winning proposal) — replaced by server-computed occurrences + `GET /cron/next`; the client never re-implements Europe/Zurich cron semantics.
- **Unconditional auto-refresh of the grid on live events** (originally in the winning proposal) — bounded by the dirty-draft/inspector guards; and the inverse blanket "never auto-refresh" reading of the mission-control graft is equally rejected: an idle committed guide updates its own trace.
- **Dual-shape transition for typed programs** (craft-ceiling) — violates the no-legacy-code policy; the swap is hard, with CLI/scripts updated in the same change.
- **Redirect stubs for deleted routes** (flow-first, craft-ceiling) — no-legacy-code policy; the 404 page carries the nav.

**Deferred scope:**

- Drag/direct-manipulation slot editing — permanently out by thesis: slots derive from cron.
- Server-side cached-last-plan fallback for the Tunarr-down Guide — held in reserve as a contract addition (see Open Questions).
- Blocks YAML import/export UI — the endpoints exist and stay CLI-served; Series gets the UI because it has no equivalent today.
- Card recomposition of Blocks/Series tables on mobile — scroll containers in v0.5.x.
- Multi-day simultaneous grid rendering / virtualization — one day-window at a time.
- SSO / oauth2-proxy integration (v0.9) — noted only as the standing requirement that the SSE stream must pass through it.
- Backfilling apply runs from before the v0.5.3 migration — impossible; the Log's empty state teaches it.
- Toasts, spinners, hamburger navigation — banned by identity, listed here so nobody reintroduces them as "mobile pragmatism."
